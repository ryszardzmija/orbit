# Engineering invariants

These properties govern future changes to Orbit. See [architecture](architecture.md) for runtime behavior and [known limitations](known-limitations.md) for evidence and remediation. The qualification in each row is part of the invariant's scope.

| Status | Meaning |
| --- | --- |
| **Enforced** | An identifiable mechanism enforces the property in the documented scope. |
| **Tested** | Existing automated tests exercise the property. This can accompany Enforced. |
| **Intended** | The property is a requirement with incomplete enforcement or verification. |
| **Suspected violation** | Static analysis identifies a plausible path that violates the property. |
| **Not established** | Available evidence is insufficient to determine whether the property holds. |

Tests establish behavior in the cases they exercise. The integration test names below refer to [`proxy_sessions_test.py`](../tests/integration/proxy_sessions_test.py). Buffer tests refer to [`SendBufferTest`](../tests/proxy/send_buffer_test.cpp).

## Resource ownership

| ID and invariant | Status | Rationale and enforcement | Existing tests and exceptions |
| --- | --- | --- | --- |
| **INV-OWN-001** Every live owned fd has one authoritative owner. | Enforced | A single close responsibility prevents double close and reuse errors. [`FileDescriptor`](../src/common/fd.h) is noncopyable. Listener, poller, pending records and session endpoints hold owning wrappers. | No direct ownership test. Raw fd integers from `get()` and in poller records are borrowed. The wrapper assumes callers construct it once per newly acquired fd. |
| **INV-OWN-002** Transfer invalidates previous ownership, and each acquired fd is closed once by its owner. | Enforced | `FileDescriptor` moves set the source to `-1`. Move assignment closes a previous target fd and destruction closes only a valid fd. The dialer moves descriptors along the lifecycle. | No direct move or close-count test. The wrapper makes one close call and ignores its return value. |
| **INV-OWN-003** Destroying a session releases its two fds and both queues. | Enforced, Tested | [`SessionManager::remove`](../src/proxy/detail/session/session_manager.cpp) erases a value owning both endpoint wrappers and buffers. Map destruction releases remaining sessions. | `test_second_shutdown_signal_force_closes_active_sessions` checks peer EOF and successful exit. It does not count fd closes or allocations. Full hangup releases the queue for the undeliverable direction immediately. |
| **INV-OWN-004** Borrowed data is used only within its owner's lifetime. | Enforced | Session handlers use local references. The poller borrows fd numbers and dispatch looks up copied registrations by ID. [`closeSession`](../src/proxy/proxy.cpp) removes source metadata before session erasure. FIFO spans and the tail pointer refer to live storage in the relevant call. | Churn gives indirect coverage. Retirement invalidates the source ID even on a kernel DEL error. |
| **INV-OWN-005** Handled failures release partially acquired resources. | Enforced, Tested | Initialization prepares socket owners and empty queues locally. A failed connection ADD or supported allocation failure releases installed watches, deadline keys and admission. Deadline insertion rolls back the first index if the second fails. | Tests cover pending and established ADD, initialization and deadline allocation failures and expiry during handoff. Unexpected rollback or flat hash table allocation failure is fatal. |

## Session lifecycle

| ID and invariant | Status | Rationale and enforcement | Existing tests and exceptions |
| --- | --- | --- | --- |
| **INV-SES-001** A connection has an unambiguous owning phase from accept through teardown. | Enforced | `PendingConnection` and the established map are distinct. `handlePendingConnection` extracts the owning record and removes its registration before completion. `addSession` inserts the session after two successful endpoint registrations. | Integration exercises successful loopback handoffs. Controlled dialer tests exercise failure, fallback and completion with a fixed deadline. |
| **INV-SES-002** A terminated session cannot be dispatched as active. | Enforced | `closeSession` erases its registrations and session. `start` resolves every event anew, and `handleEndpoint` checks membership and stops dispatch on close. | `test_session_churn_does_not_disturb_an_active_session` is indirect. Controlled dispatch tests inject events after removal. |
| **INV-SES-003** Multiple events and repeated teardown for a session must preserve unrelated sessions. | Enforced | [`ReactorSources`](../src/proxy/detail/sources/reactor_sources.cpp) binds source IDs to a session ID and endpoint role or another registration type. `closeSession` returns for an absent session and retires only the two relevant watched source IDs. | Reset isolation and churn give indirect coverage. Controlled batches cover single-source retirement and session teardown during multi-flag handling. |
| **INV-SES-004** Numeric fd reuse cannot redirect a stale event to an unrelated connection. | Enforced | [`EpollPoller`](../src/proxy/detail/epoll/epoll_poller.cpp) returns value IDs independent of fd numbers. New registrations get new source IDs and retired IDs are removed. | `RetiredSourceCannotDispatchToAReusedDescriptor` verifies actual fd reuse and stale-event rejection. The 64-bit ID generator's wrap policy is unspecified. See [LIM-008](known-limitations.md#lim-008--source-identities-have-no-wrap-policy). |
| **INV-SES-005** A pending completion establishes, advances to a fresh attempt, or terminates with the appropriate owner released. | Enforced | [`UpstreamDialer::advanceDialAttempt`](../src/proxy/detail/upstream_dialer.cpp) checks `SO_ERROR`, closes a failed attempted fd before candidate fallback, and returns owning pending or connected values. | A monotonic deadline also terminates the sequence. Controlled tests drive failed completion, fallback and expiry. Shutdown policy is covered by INV-SHD-003. |
| **INV-SES-006** Total and pending admission stay within the configured limits. | Enforced, Tested | The pending and established maps and the scoped transient reservation account for admissions. The listener reserves both slots before accept. Promotion keeps the total slot and releases the establishment slot. Fallback closes the failed socket before replacement. | Tests exercise both limits, promotion at capacity, failed and expired establishment, and forwarding with suspended admission. |
| **INV-SES-007** Listener resumption requires current admission eligibility. | Enforced, Tested | Listener interest is synchronized after dispatch and every accept checks both limits and the running shutdown state. Shutdown retires the listener. | A controlled test verifies absent listener readiness while a client is backlogged, stale readiness rejection and resumption after expiry. Loopback verifies backlog recovery after an established session closes. |
| **INV-SES-008** Resource-pressure suspension expires without connection turnover. | Enforced, Tested | A separate retry timestamp disables listener interest and prevents new socket attempts during cooldown. On expiry the shared timer reevaluates capacity and shutdown state. | Controlled tests check repeated errors, copied readiness, conflicts with admission limits and shutdown. Loopback restores Orbit's descriptor limit with an established session still open. |

## TCP forwarding

| ID and invariant | Status | Rationale and enforcement | Existing tests and exceptions |
| --- | --- | --- | --- |
| **INV-TCP-001** Byte order is preserved independently in each direction. | Enforced, Tested | [`Forwarder::forward`](../src/proxy/detail/forwarding.cpp) attempts direct send only with an empty destination queue. The `SendBuffer` FIFO preserves the existing prefix ahead of newly read bytes. | `BufferPreservesInputDataOrdering`, `BufferCorrectlyHandlesWriteConsumeCycles` and both integration transfer and half-close cases. The controlled hangup tests check FIFO delivery after a verified pause in both directions. |
| **INV-TCP-002** Bytes read in a continuing direction are submitted to the destination TCP stream once, barring connection failure or intentional termination. | Enforced, Tested for normal forwarding | `Forwarder` queues the exact unsent suffix. [`PendingDataSender::sendPending`](../src/proxy/detail/pending_data_sender.cpp) peeks and consumes the reported count. This accounts for bytes accepted by the kernel. | `test_large_bidirectional_transfers_survive_backpressure` checks payload equality. Per-syscall partial progress is uncontrolled in this test. |
| **INV-TCP-003** Partial writes and would-block retain every unsent byte. | Enforced | Normal and buffered sends use the actual returned count. Would-block reports zero, preserving the remaining data for later `EPOLLOUT`. | Queue consume unit tests and long integration transfers are indirect. The saturated socket tests force zero-progress direct and queued sends. Exact positive partial sends remain uncontrolled. A hard send failure closes the session. |
| **INV-TCP-004** A peer half-close leaves the opposite direction available. | Enforced, Tested | [`SessionManager`](../src/proxy/detail/session/session_manager.cpp) tracks EOF, peer-half-close and write shutdown separately on both endpoints. `halfCloseIfReady` uses `SHUT_WR` on the destination. | `test_client_half_close_is_propagated_after_data` and `test_backend_half_close_keeps_client_to_backend_direction_open`. A reset or full hangup takes a separate path. |
| **INV-TCP-005** Orderly write shutdown follows source EOF and flush of all preceding bytes. | Enforced, Tested | Actual EOF and an empty destination queue trigger `SHUT_WR`. A successful shutdown is recorded once. EINTR retries and terminal failures close the session. | EOF-only dispatch, deterministic ENOTCONN and both loopback half-close directions have regression coverage. |
| **INV-TCP-006** EOF, temporary unavailability and hard I/O errors represent different outcomes. | Enforced | [`tryRecv` and `trySend`](../src/net/socket_io.cpp) keep EOF and would-block distinct, retry `EINTR` and return other errno values as errors. Normal read EOF sets `done_reading`. | Half-close and reset cases give indirect coverage. The controlled would-block hangup test verifies that input remains eligible. |
| **INV-TCP-007** Forwarding uses bytes independently of application framing. | Enforced, Tested | Socket I/O takes byte spans and preserves data across local chunk boundaries without parsing payloads. | Raw binary transfers and length-framed harness messages traverse the same proxy. The harness supplies its own framing. |
| **INV-TCP-008** An established stream stays paired with its original upstream socket. | Enforced | `SessionManager::add` stores the two owning fds. No established handler replaces the upstream or replays data after failure. | Churn tests exercise multiple separate pairs. Upstream outage after establishment has reset coverage, with no future routing policy in the existing code. |

## Buffering and backpressure

| ID and invariant | Status | Rationale and enforcement | Existing tests and exceptions |
| --- | --- | --- | --- |
| **INV-BUF-001** Pending bytes belong to exactly one forwarding direction. | Enforced, Tested | Each `SessionEndpoint` owns its destination's queue. Role lookup pairs the readable source with the opposite endpoint and the writable endpoint with its own queue. | `test_large_bidirectional_transfers_survive_backpressure` checks distinct payloads in both directions. |
| **INV-BUF-002** Logical occupancy equals the bytes available to copy, and consumption advances by the transmitted count. | Enforced, Tested | [`SendBuffer::writeData`, `copy` and `consumeData`](../src/proxy/detail/buffer/send_buffer.cpp) maintain byte count and offsets. The sender consumes the actual send result. | Buffer tests cover FIFO bookkeeping. A controlled reactor test verifies exact delivery after a partial send and a would-block result. |
| **INV-BUF-003** Every read that may enqueue data respects destination admission. | Enforced, Tested | All reads share the admission check immediately before forwarding. A hung-up source can remain unread while its destination is paused. | `HangupTest` establishes socket saturation and the watermark transition, then checks the unread kernel prefix, bounded resumption, delivery and EOF for both roles. |
| **INV-BUF-004** Reads pause at the hard logical limit and can resume at low occupancy. | Enforced, Tested | Each receive is limited to the queue's admissible bytes. The queue independently rejects oversized and paused appends. Reaching high pauses admission and reaching or crossing low resumes it. | `SendBufferTest`, `ConfiguredWatermarksLimitReadsAndPreserveAPartialSendSuffix` and both residual hangup directions. |
| **INV-BUF-005** Re-enabling ordinary read interest allows remaining data and EOF to make progress. | Enforced | The reactor uses level triggering and reinstates `EPOLLIN` using MOD. Existing readable data or EOF can report readiness again. | Large transfers and half-close cases give indirect coverage. The surviving destination continues a residual drain through writable progress. [`epoll(7)`](https://man7.org/linux/man-pages/man7/epoll.7.html). |
| **INV-BUF-006** Allocated directional payload capacity counts every live block. | Enforced, Tested | For logical limit `H` and block size `B`, capacity is bounded by `ceil((H + B - 1) / B) * B`, including front slack and tail rounding. An empty queue owns zero blocks. | Queue tests cover exact limits, live head slack, partial block reclamation and overflow validation. |

## Reactor

| ID and invariant | Status | Rationale and enforcement | Existing tests and exceptions |
| --- | --- | --- | --- |
| **INV-REA-001** Data-plane sockets are nonblocking and handlers avoid indefinitely blocking network I/O. | Enforced | [`net::Listener::create` and `acceptClientConnection`](../src/net/listener.cpp) and [`net::dial`](../src/net/dialer.cpp) request nonblocking fds. Resolution is synchronous during creation. The intentional steady-state wait is central in `EpollPoller::wait`. | No direct fd flag test. Nonblocking sockets do not bound total work inside a handler. |
| **INV-REA-002** Interests reflect the current lifecycle, with writable interest reserved for pending connect or queued output. | Enforced | `registerPendingConnection` adds upstream `EPOLLOUT`. Newly installed sessions request `EPOLLIN` and `EPOLLRDHUP`. `getInterests` requests `EPOLLOUT` for a live destination with a nonempty queue. `synchronizeEndpoint` retires a hung-up source after residual EOF. | The hangup tests check admission and trigger mode. This describes current registrations. Earlier copied masks are covered by INV-REA-005. |
| **INV-REA-003** Connection-local failures and supported resource failures preserve independent established sessions. | Enforced, Tested | Failure classification uses the operation and error code. A recoverable failed connection or incomplete append closes its pair and releases its owners. Integrity failures remain fatal. | Reset isolation, injected accept and dial pressure, endpoint registration and interest failures, and supported allocation fault tests. See [LIM-013](known-limitations.md#lim-013--resource-exhaustion-can-stop-the-reactor). |
| **INV-REA-004** Established endpoint error and hangup do not keep reporting after exit from their lifecycle. | Enforced, Tested | `EPOLLERR` closes the pair. A retained hung-up source uses edge triggering until residual EOF, then retires. | The idle CPU integration case and an epoll test holding a paused, hung-up source until idle expiry cover persistent HUP. A reactor-wide bound under persistent readiness or failure is not established. |
| **INV-REA-005** A copied readiness event cannot authorize I/O forbidden by newer endpoint state. | Enforced, Tested | Dispatch resolves the current registration. Per-operation read and write checks consult the source, destination and queue. A close or retirement stops the remaining flags. | `ProxyReactorTest` drives stale masks and verifies that the surviving direction flushes. The saturated queue tests also inject stale readable observations. |
| **INV-REA-006** Measured service latency stays bounded under mixed sustained workloads. | Not established | The batch and normal I/O size limits restrict some work. Candidate scans lack a comparable iteration budget. | The idle CPU test does not measure progress across busy sessions. See [LIM-009](known-limitations.md#lim-009--reactor-work-budgets-are-incomplete). |

## Configuration

| ID and invariant | Status | Rationale and enforcement | Existing tests and exceptions |
| --- | --- | --- | --- |
| **INV-CFG-001** Input validation follows the documented rules, including the handling of invalid values. | Enforced, Tested for upstream, timeout and resource parsing | [`parseConfig`](../src/config/config.cpp) validates endpoint syntax, port bounds, timeouts and resource settings. Timeout and resource values are checked after CLI/environment selection. CLI11 can silently ignore invalid listen-port and log-level environment values. | Configuration tests cover precedence, limits and relationships. See [LIM-015](known-limitations.md#lim-015--invalid-environment-settings-can-revert-to-defaults) for legacy scalar handling. |
| **INV-CFG-002** Runtime uses supported settings and documentation identifies accepted settings with no runtime effect. | Enforced, Tested | `main` passes the selected endpoints, timeouts, resource settings and log level to their consumers. [Configuration](config.md) describes later upstream entries. | Config tests exercise precedence and resource validation. A reactor test exercises configured watermarks. See LIM-002 and LIM-007. |
| **INV-CFG-003** Resource parameters satisfy the queue's required relationships. | Enforced, Tested | The `SendBuffer` constructor requires positive block size and high watermark, block size at most high, and low below high. A zero low watermark is valid. | The `SendBufferTest.BufferConstruction*` cases exercise valid and invalid relationships. Runtime supplies constants. |
| **INV-CFG-004** Endpoint syntax, address family and address length stay consistent through resolution and socket setup. | Enforced, Tested for syntax and formatting | The parser strips upstream brackets and holds host and port separately. [`net::resolve`](../src/net/resolver.cpp) produces `SocketAddress` values with correct lengths and sockets use the candidate family. | Config DNS and address parsing tests, [`FormatAddressTest`](../tests/net/address_format_test.cpp) and IPv4 loopback integration. Controlled fallback has loopback coverage. Live IPv6 forwarding remains untested. |

## Shutdown

| ID and invariant | Status | Rationale and enforcement | Existing tests and exceptions |
| --- | --- | --- | --- |
| **INV-SHD-001** A successful transition to graceful shutdown prevents further listener admission. | Enforced | `handleShutdownRequest` unregisters the listener and resets the owning optional. Subsequent events using the listener's old source ID cannot dispatch. | The pending-only test injects a copied listener event after graceful shutdown starts. Earlier events can admit before the request is handled. |
| **INV-SHD-002** Established sessions keep forwarding during graceful shutdown until normal teardown or escalation. | Enforced, Tested | The main event loop uses normal handlers during `GracefullyStopping` and `shouldStop` waits for the established map to empty, absent a timer, another shutdown request or fatal error. | `test_graceful_shutdown_waits_for_active_session` checks live traffic during drain and exit. The mixed shutdown regression expires the one-shot timer with an established session. |
| **INV-SHD-003** Starting graceful shutdown cancels every pending dial. | Enforced, Tested | Completion and cancellation share source retirement and extraction. Only established sessions can survive the transition. | Controlled pending-only and mixed cases check resource release, stale completion and subsequent forwarding. |
| **INV-SHD-004** Forced shutdown releases remaining owned resources without dispatching teardown state as live. | Enforced, Tested for established sockets | `forceCloseAllSessions` uses normal map and source retirement. `HardStopping` ends dispatch. The first request already emptied the pending map. RAII releases the shutdown descriptors and poller at exit. | `test_second_shutdown_signal_force_closes_active_sessions` verifies exit and EOF on both established endpoints. It does not check pending sockets, queued bytes, or precise timer dispatch latency. |

## Deadlines

| ID and invariant | Status | Rationale and enforcement | Tests |
| --- | --- | --- | --- |
| **INV-FUT-001** Bound the entire upstream establishment sequence. | Enforced, Tested | One time source defines the deadline and checks it across candidates, retries, socket preparation and handoff. | Controlled fallback verifies descriptor release and continued forwarding for an established session when the deadline expires before `connect()`. Retry, expiration at completion and handoff, and real timerfd cleanup have regression coverage. |
| **INV-FUT-009** Cancel scheduled work across teardown and shutdown. | Enforced, Tested | A typed key is tied to a single lifetime. Cancellation removes the ordered entry and its index. Each timer dispatch handles at most 64 due entries. | Ordering, rescheduling, cancellation, equal deadlines, stale events and burst continuation have controlled coverage. |
| **INV-SES-006** Idle expiration is optional and measures positive socket transfers in either direction. | Enforced, Tested | Establishment creates the first idle key when enabled. Each forwarding step checks the deadline. Only positive socket transfers observed strictly before the current expiry refresh it. Expiry closes the session and teardown cancels the key. Half-close and queued output retain the same policy. | Controlled tests cover expiry between readiness flags, the activity cutoff, and deferred hangup progress. The disabled path is checked for zero idle clock reads during forwarding and teardown. A configured loopback process verifies expiry through the CLI. |

## Future engineering constraints

All entries below have **Intended** status. The named components identify the likely enforcement points. No current automated test establishes these guarantees. Each verification item describes coverage to add when the requirement is implemented.

| ID and required property | Rationale and component boundary | Verification to add and current gap |
| --- | --- | --- |
| **INV-FUT-004** Account for global application-managed buffer memory. | Coordinate queue ownership and admission to maintain a process-wide payload allocation budget. | Reconcile concurrent allocations and releases with the configured budget. Observe process and kernel memory separately. |
| **INV-FUT-005** Budget work fairly across reactor sources. | Schedule accepts, connection attempts, reads, writes and drains so one source cannot delay all others indefinitely. | Measure mixed-workload service latency with hot and idle flows. Current bounded chunk and accept sizes cover only some work. |
| **INV-FUT-006** Track upstream connection usage. | Account for pending and established lifecycle transitions per upstream for routing and admission. | Verify increments and releases across failed, retried, completed and cancelled connections. Current maps carry no per-upstream counters. |
| **INV-FUT-007** Route new connections using explicit upstream health and eligibility. | Apply decisions at dial start and preserve pinned established streams. | Verify selection and degraded behavior with multiple configured entries. The dialer currently chooses addresses for one endpoint. |
| **INV-FUT-008** Bound connection retries. | Limit attempts and time with an explicit candidate and upstream policy. | Verify attempts, total time and cleanup under failure. M1.4 bounds the address walk by time. Per-address time slicing and cross-upstream retry remain outside the runtime. |
| **INV-FUT-010** Keep health monitoring nonblocking. | Ensure health work fits the reactor's nonblocking and fairness requirements. | Measure continued data-plane progress during slow health checks. No health monitor exists. |
| **INV-FUT-012** Make performance characteristics measurable. | Validate reactor and buffer choices with reproducible throughput, latency, CPU and memory measurements. | Record representative workloads and environment details. The current idle-CPU test is a regression check with limited scope. |
